# Functional Requirements: Day Planning and Month Materialization

**Status:** Implemented and verified  
**Format:** One atomic requirement per row, one continuous identifier sequence, implementation-module ownership, and automated-test traceability  
**Scope:** Planned work, schedules, month materialization, day classification, calculation, import/export, month lifecycle, carry-over, concurrency, and timer behavior

## Terms

| Term | Definition |
|---|---|
| Planned minutes | The integer value stored in `day_entries.expected_work_minutes`. |
| Schedule | An effective-dated policy stored in `work_schedule_periods`. |
| Special day | Any non-normal classification, including `Weekend`, `No data`, vacation, sick leave, or custom text. |
| Materialized month | A month and all of its calendar-day rows persisted in SQLite. |
| Virtual month | A month rendered from calendar and schedule data without a `months` or `day_entries` row. |
| Open result | A result calculated from the current persisted day inputs. |
| Closed result | A frozen result stored in `closed_day_results`. |
